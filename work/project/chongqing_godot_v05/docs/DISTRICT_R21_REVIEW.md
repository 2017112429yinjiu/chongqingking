# R21 城区环境工作记录

## 从哪里打开

Godot 4.6.3 Forward+ 的常规入口是本工程的 project.godot。main.gd 默认读取 assets/render_profile_r21.json，先实例化保留的 R17 基础城市，再装配 R19 街道、R20 上巷和 R21 环境。R21 的建筑增量位于 assets/district_r21/terraces.glb。完整可编辑城市源为工作区的 work/scene_r21/chongqing_district.blend；同目录 district_environment.blend 可单独打开。整城以 Blender 4.3.2 复开后有 2,984 个对象、185 张打包图，独立环境场景有 51 个对象。

## 保留的视觉试验

最初的坡体、树冠和雾一起压低了远景对比，屋顶视角几乎看不清。随后减弱雾，增加窗下雨痕和屋面层次。第三次的石板发白，第四次压低反照率、调整石侧色和栏杆表面。另用两组太阳方向在同机位复拍，采用与天空亮区协调的东向日照，再压低主光能量、放软树荫边缘。第六次根据低机位原图补街口和上路侧砌，减弱过于均匀的铺地棋盘格。历史画面分开保存在 verification_r21/district01 至 district05、light_east；第五次的完整源和图层副本在 work/scene_r21/district_trial05。

第七次放大屋顶视角后发现，外围树干在灰坡上留有一道平直亮边。利用原扫描树的八个方向图和当前太阳方向，将树冠遮光与树干近地遮蔽写进独立地表图，树干基部的天光也相应减弱。623 个树位分别检查。日照是固定的，投影以水平接收面近似后铺到外圈地形，接近地表处仍可辨出树冠替身。完整 Blender 源与第六次相同；这项改动在 Godot 的外围地表和树冠材质上生效。

另用 180、112、112、180 米顺序，四次独立启动比较街道的太阳阴影范围。中央梯坎 P95 依次为 22.883、17.513、23.029、22.353 毫秒。较短范围在这个机位的收益未稳定复现，屋顶的一部分远景失去直接阴影。现行配置保留 180 米。原图、帧时和逐机位像素差保存在 verification_r21/shadow_study。

## 复现

1. work/fetch_district_r21.py 记录上游文件、许可、MD5 及本地 SHA-256。work/bake_district_trees.py 生成八张扫描树方向图，work/prepare_district_r21.py 组图、制作石材颜色版本并重建日照配置。
2. 用 Blender 4.3.2 后台打开 work/scene_r20/chongqing_district.blend，再执行 work/build_district_r21.py。建筑、压顶、窗挂物、踏面、路沿背衬都可在新整城里直接编辑。work/bake_facade_weather_r21.py 与 work/bake_outer_land_r21.py 生成材质分区图。运行 work/bake_exterior_sun_r21.py 利用同一批树位与日照配置生成外围地表遮光。运行 work/audit_district_r21.py 复开两个保存的 .blend 并核查资源与高度。
3. work/verify_district_r21.ps1 提供 import、capture、district、lane、gameplay、delivery、survey、character、performance 和 movie。另有 defects、street、rider，用八个诊断机位复查旧缺陷位置，并实际运行街道与骑手测试。默认 Run 为 current，其他试验请指定另一证据目录。视频用 work/encode_district_r21.py 裁去启动时间、转码并重新读取编码流核对帧数和尺寸。work/record_district_review_r21.py 以展示输出目录为参数，核对当前模型/配置哈希、测试报告和相机后生成对照图。
4. 九张原始实机 PNG 位于 verification_r21/current/captures。基线同机位原图在 verification_r21/district_base/captures。电影走拍在 work/scene_r21/district_current.avi 和 .mp4，从真实碰撞面采样 15.2 米轨迹，镜头以约 1.65 米眼高平滑前进。视频无剪接、无调色、无声，共 241 帧、30 fps、1280 × 720。work/review_district_video_r21.py 独立解码保存的 MP4 全部 241 帧，留存九个时刻的画面。玩家实际输入与骑行移动另由整单测试检查。
5. 两次独立进程在同一台 RTX 4070 Laptop GPU 上测 1080p，六个固定视角各预热 90 帧，再采 240 帧。verification_r21/perf_reference 使用本轮运行代码并选 R20 美术配置，current 使用 R21。原始数据同时给出中位、平均、P95、绘制调用及图元。帧时包括游戏帧的开销。

## 保留的人物与交互

同一版本已在实际引擎跑过城区 20 项、骑手 20 项、街道 11 项、上巷 42 项、店主动作 20 项、基础玩法 24 项、整单 11 项。24 条路线共 261 项巡查通过。首次整单的阶段之间没有传送。另用八个既有诊断机位检查原六张缺陷图对应的物件及周边，此次拍摄与原用户自由相机角度不完全相同。各配置和原始截图的哈希在 verification_r21/current/review_summary.json。

店主可编辑源在 work/characters/shopkeeper_r21/shopkeeper_authoring.blend，餐台调料在 work/scene_r21/condiments/counter_condiments.blend。右手把整份餐从备餐侧移往顾客，左手配合托袋；围裙胸片与下摆在动画中受力。装杯分支、首次整单、树池问路和骑行沿用同一交互入口。第二单专项从已完成一次送餐的夹具开始。人物动作与城市日照的验收分别记录。

## 当前观感与缺口

树池后方现在有可读的石坎与树冠遮挡，街口的踏板也能看到侧面支承。屋顶镜头中的若干楼群仍共用近似窗格和屋面色，外围树冠只有两种扫描来源，道路与上巷硬地仍显空。连续上阶时能明显感到两侧栏杆规律平行，主要生活动作还集中在店主和树池街坊。后续场景制作要从行人经过的两个路口、楼下可见的室内纵深与屋面用材差异入手。此轮未完成艺术验收，也未封包。

R15 两个 Blender 归档、Godot 归档及六张用户缺陷截图均保留。原 R15 最终照片包仍未找回。重要原件与验证结果分别归档。
