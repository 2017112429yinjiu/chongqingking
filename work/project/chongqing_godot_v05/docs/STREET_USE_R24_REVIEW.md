# 重庆街面实拍对照 · R24 构建 12

## 在游戏里看

从「菜摊到货处」往前走，先经过两轮板车，靠近时能看到筐板上的木纹、台边洗菜盆和摊边的价签。从「西巷梯坎与院路」上行，留意踏面、立面与墙边的颜色，再看右侧窗下的花架。南区路机位可看车行道与人行道之间的明度差异。

实拍、前后原帧、图板、源文件、接触测量和运行日志均在 `work/scene_r24/street_photo_study`。运行项目在 `work/project/chongqing_godot_v05`。布光沿用上轮白天设置。内部构建，艺术验收待玩家实走。

## 源文件与迭代

整城源 `city_and_street_use.blend` 从构建 11 的 `city_and_block_r24.blend` 另存。Godot 复用既有城区和城市框架，加载 `assets/street_use_r24/workday.glb`、摆放清单和两张空间纹理。花架用原有盆栽网格，板车、花架和菜摊工具有独立可编辑几何。木板、竹条和旧漆沿各自构件的方向取样，纸板字牌及木料贴图随道具打包在 GLB 中。资产哈希、五种既有扫描来源、字体来源及许可在 `asset_record.json`。路网仍随原有投影数据保留 OpenStreetMap 署名。

第一轮复拍暴露出沿街摊架的一处着色器编译错误，失败帧和错误日志留在 `candidate` 及 `candidate.log`。第二轮从顾客来向调整价签，按支承面法线摆正竹筐和脸盆。此后限制了补浆所属的地表，减少了墙脚和石阶材质的重复取样。对着近机位又检查了一轮板车，给无纹理的平板换上原工程扫描木料并保留实测轮轴。最终游戏原帧在 `final`，前后图板从磁盘上的实际截图生成。

## 复查入口

- `run_review.ps1 -Phase final` 使用主工程默认配置采集十个 1280 × 720 固定机位。`before` 与 `before_extra` 保存对应的旧版画面。
- `inspect_support.gd` 将 Blender 选定的接触点与 Godot 地面碰撞重新比对。板车和花架有单独的阻挡体，落地测量时排除这两件道具自身。
- `run_review.ps1 -Phase walk`、`market`、`delivery` 和 `smoke` 检查四段梯坎、沿街步行、外卖流程与场景启动。测试结果在游戏的 `verification_r24/build12`。
- `walk_market_take.gd` 用玩家控制器连续经过摊前。`走过菜摊.webp` 采用实跑录到的帧，`motion/continuous.json` 保留采样位置和最大单步位移。
- `paired_gpu.ps1` 在同一块显卡顺序测旧版和当前版本。每个机位记录 240 帧 GPU 时间。不同次测量波动明显，须结合采样文件、分辨率和当时的机器负载看待。

本轮近景集中在菜摊、修车点和西巷门口。离开这些点，店之间的铺面仍长而空，檐下阴影与树荫不足，远看立面开窗的节奏仍过于整齐。原城市框架的发行许可复核沿用构建 11 的状态。


## 2026-11-21 实测记录

Godot 4.6.3 导入并运行当前默认工程，十组新旧截图的相机位置、目标、视角与尺寸逐一相同。24 个支承点都有地面命中，Blender 与 Godot 在这些点的最大高度差为 0.05 毫米以内。这是对坐标与接地规则的核查，形体观感另以实拍和走动记录评判。Blender 4.3.2 重新打开了完整编辑源，十个原创建模网格及六个盆栽部件可见于文件，价签图片已内嵌。

摊前连续走过 8.44 米，录得 32 帧。62.39 米的市场路线、四段梯坎接缝和外卖全程都通过了本次控制器测试。修车摊与主路远景保留为后续步行观察点。前后原帧的 SHA-256 和检查结果在研究目录的 `review_result.json`。

原生 1920 × 1080，RTX 4070 Laptop GPU，各测 240 帧。最后一组顺序复测中，西巷踏步的 GPU 中位 / P95 从 29.93 / 35.15 毫秒变为 29.33 / 31.95 毫秒。菜摊从 70.52 / 84.77 毫秒变为 71.49 / 79.73 毫秒。其他轮次在同机上波动很大，最后这组菜摊仍超过 30 帧/秒的预算。原始 GPU 帧、场景指纹及逐机位摘要存于 `verification_r24/build12/pair_verified`。

交互试玩窗口标题现取自实际载入的艺术修订号，当前显示 R24。
