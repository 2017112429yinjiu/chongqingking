# 车辆系统

R22 的六辆远景公交、客车及厢车按两条桥轴、不同车速与相位运行。车辆共享流程，始终处于远景层。进出桥头短暂隐藏，路线按时间重算。检查前进方向、三秒位移、循环和显隐。可骑电瓶车继续由 scooter_controller 和骑手系统控制。近中远车辆间的身份交接尚未实现。

R21 新增梯段侧砌体、路沿背墙与树干，保留原骑行路线和物理踏面。跨增量时以 delivery_end_to_end.json 检查真实驾驶经过各阶段，结合 survey.json 的区域巡查检查固定通道。当前交通流量和车辆日程仍待扩展。
R18 开发版沿用 99 号原创电瓶车几何，以独立 Blender 源拆分后轮、前轮、转向把、前叉和脚撑；另外六辆城市静态车不变。CharacterBody3D 街道驾驶：前进上限 6 m/s、倒车 1.8 m/s，W 前进、S 先刹车后倒车，A/D 转向、空格急刹、P 停车、E 下车。无跨启动存档和真实悬架。

`scooter_visual.gd` 只负责显示和接触姿势：按实际位移/0.236m轮胎半径旋转车轮，撞停时不空转；转向姿态从原始双手 IK 采样，视觉与驾驶转向一致；停车左脚先抬出踏板再落地，起步收脚，脚撑在无人停车时伸出。年轻骑手采用核查 MIT 的 Rocketbox 人体，原创动作/头盔，店主不受此替换影响。`rider_r18.glb.import` 单独关闭动作优化，采样补偿 Blender 导出首键 1/30s。停稳和行驶姿势有过渡，但进/出车辆仍是第一人称与骑行状态切换，尚未完成全身跨上/跨下动画。

静态七辆车通过 Blender 实际路面 BVH 检查轮胎下缘，拟合车身俯仰和高度；不使用统一抬高量。驾驶时物理盒保持竖直，前后轮探测调整模型俯仰。其横坡贴合和陡坎表现仍需专项测试。

上车暂停步行输入与碰撞；下车必须停车且四个候选位置存在可站立地面、身体空间和不穿墙的连线。全部被挡时拒绝下车。速度归零后确认停车，禁止瞬间下车保留车辆速度。

物理外形宽度补足至把手宽0.74m，并在有人骑行时开启上身胶囊，避免头部从低障碍穿过。下车先写退出位置，碰撞掩码在帧边界恢复。只调用 force_update_transform 或直接写 PhysicsServer 状态不能消除同一物理步中的旧位置；实测原流程会挤动车辆约0.7m，延后恢复掩码后车位保持检查为0位移。步行控制在退出后恢复，碰撞在当前帧末恢复；QA等待帧边界后检查真实状态。失败/定位日志在 work/audit/rider_exit_*.log，不能删除失败历史或改称原流程一直正确。

专项入口 `--r18-rider-test`：当前街道路面实驶、车轮滚动、转向时双手误差、刹停支撑、倒车、停车/下车及车位保持，固定截图在 verification_r18/rider_current。单个道路试验不等于全部横坡、陡坎或全身连续碰撞验收。

后续车辆类型通过配置共享控制接口；性能与输入由控制器负责，美术模型只提供座位、轮轴、出口锚点。道路图必须禁止楼梯、坡度过大及过窄路段。当前没有 AI 交通。

R17 另外验证面馆真实停车点出发、实际骑行、停车下车后连续步行入户；这不代表车辆可以进入所有阶梯路线。
