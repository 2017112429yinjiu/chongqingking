# NPC 与交通模拟架构

R22 有六辆远处过桥的可见车辆。采用两条双向分离的路径，车辆外观随时间更新，路段外隐藏。这里没有生成乘客、行人日程、避让或导航请求。步行街里的店主及邻居继续独立更新，远车不能向他们派单。

本轮将人物工作冻结在现行店主及树池街坊，把城区可见植被与居民模拟分开。外围树冠由空间分块渲染；这些树不生成日程、车辆或步行任务。21 处近景植栽中只有五个树干新增实心碰撞。现有街坊的远近更新规则仍适用。城区通勤密度和路口等候行为仍是待实现的生活感来源。

R20 在上巷树池放置了一位有独立身份的常驻街坊。她与面馆店主使用不同的模型和动作。玩家可以问面馆位置，携餐时会获得住宅门牌提示。居民的活动时钟跨距离保留。近处逐帧更新，离开 27 米后骨骼约每 0.18 秒采样一次，超过 70 米隐藏模型并停止写入骨骼姿势。从远处返回 65 米内或从中距离返回 22 米内分别恢复上一级。当前只对这一位坐着的居民实施了这部分设计，实例和碰撞体仍驻留。下文的通勤日程、行人寻路与多实体负载属于后续工作。
R18 已实现一名带骨骼和碰撞的店主、实录待机/原创取放/点头、双眼注视、眨眼微笑、重复订单与住宅门铃。58 骨骼包含两眼与三片下摆骨骼。没有运行行人群体、NPC 日程、AI 车流或完整导航网。以下架构仍为待实施设计。

R18 另有可见玩家骑手，供电瓶车驾驶时显示，使用独立81骨骼人体与原创接触姿势。它不是自主 NPC，不计作已实现行人或车流模拟。近中远分层的骨骼/动画预算以后应把玩家骑手作为始终近层的独立开销。

实体数据与可见节点分离。EntityRecord 保存 stable_id、角色、当前位置/道路边、时间、日程索引、目的地、任务和随机种子。SimulationClock 用统一游戏时间；跳时按日程落位，不逐帧补算全部历史。

近层 <=25 m：10 Hz 决策、60 Hz 物理和局部避障；中层 25–70 m：2 Hz 沿已验证路线推进、降低动画频率；远层 >70 m：0.2 Hz 按路线长度和事件时间推进，无骨骼和碰撞节点。分层采用 5 m 滞回、至少驻留 2 秒，屏幕内避免突现。数值是初始预算，必须以实测调整。

日程包含回家、营业、备餐、采购、上下班、休息。订单中断闲置并以幂等事件恢复。仅近层向 NavigationServer3D 申请路线，集中排队每帧最多 2 次；目标变化、路线失效才重算。

步行导航与车辆道路图分离。楼梯只允许行人，小车不进窄巷。按实际碰撞烘焙，门洞、桥梁、楼梯用明确连接；分块异步更新并等待地图同步。交互靠近点必须有身体空间。R17 的连续步行路径是 QA 路径，尚不是 NPC 自动寻路结果。

跨层保留 ID、订单、路线进度和时钟；不得复制实体/订单。车辆用车道图、停靠点、路口预约与跟车，近层再依赖物理碰撞。QA 应覆盖 25/100/250 实体、固定种子回放、跨层长跑、堵塞恢复、楼梯禁行、无重复实体、路径有效率、P50/P95 帧时/CPU/内存；当前这些群体测试均未执行。
