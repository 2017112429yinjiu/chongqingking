# 交互系统

R22 的茶具与早餐遮雨棚用于街边环境叙事，目前没有交互提示。电瓶车、店主、投递点及上巷设施沿用原入口。重测整单时应从接单一路骑行、停车、步行到投递点，并核查阶段间瞬移次数。

R21 沿用近距离 E 交互。第二次及之后的偶数单会开出“辣子另装”小票，店主备好餐后先将封好的调料杯放稳，再提餐袋。装杯进行时重复按键不会越过装杯状态。整单首单实走和第二单的隔离夹具分别记录在 verification_r21/current/delivery_end_to_end.json、district_test.json。

树池街坊复用和面馆、车辆相同的距离与视线检查。在居民前方步行靠近后按 E 问路。普通状态提供面馆位置，携餐时提示山城里小院一号和门铃。问路会触发人物张望动作及文字回应，保留玩家订单和收入。两处可坐的位置独立于居民所在座板。

R20 上巷告示可逐条阅读，水龙头可手动开关，开启五秒后会关闭。树池南北各有一处休息点。坐下时可以转动视角，E 起身，切换模式或复位会结束休息。起身时视角回到接近座位时的人物位置。休息使用第一人称视角。这些交互沿用世界距离与遮挡检查。
interaction_target 定义稳定 ID、提示、可用条件、执行动作和半径。interaction_manager 注册目标、筛选最近目标并在执行前重新检查步行状态、距离、世界遮挡；穿墙与远距离交互拒绝。

R17 注册 16 个目标：面馆、送达点、电瓶车、13 个住宅门铃。门铃使用原创建音效和回应文本；私人户门尚不能打开进入。任务送达点为山城里小院 1 号真实门厅前的可站立位置。

订单 AVAILABLE→PREPARING→READY→CARRYING→DELIVERED。R18 备餐 3.35 s，覆盖完整取放演出；取餐后纸袋隐藏，交付只计一次 8 元配送收入。送达后可回店接下一单。当前订单目的地固定、收入只在本次运行保存，尚无存档和完整经济系统。

店主为 MPFB CC0 人物与衣服、原创裁剪围裙，58 骨骼，带 idle/serve/greet 与实体碰撞。待机使用经署名的 100STYLE CC BY 4.0 实录相对动作，10 秒循环；serve/greet 为原创 30Hz IK 烘焙。取餐 1.12 s 握住提手，随后纸袋实际跟手，2.4 s 放回台面，3.2 s 收手；取餐台依据真实释放位置对齐。按距离注视、近身点头、眼睑与微笑已接入；尚未达到正式电影级角色表演标准。围裙为蒙皮与次级下摆骨骼，不是实时布料解算。

取餐袋为原创折叠纸袋、收拢纸带提手和面馆标签，含封口餐碗与筷子纸套；备餐期间显示并跟手，READY 时放在桌上。尚无玩家持袋手臂、骑手或外卖箱装载可视化，不能把拾取隐藏当作完整携带动画。

店主迎客识别前方约126度范围内的新到客人，3m触发、离开4.5m或转至背后2秒后重置，同一站定客人不会定时重复点头。眼球响应快于头部，备餐过程关注餐袋提手；该行为只服务当前固定店主，尚不是群体感知系统。

电瓶车交互要求停车后安全退出，见 VEHICLE_SYSTEM.md。qa_gameplay 检查边界、幂等与再次接单；qa_delivery 只有一次初始摆位，此后接单、步行靠车、实际骑行、停车下车和步行入户都不在步骤间传送。
