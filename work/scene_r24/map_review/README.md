## 这几次刷新留下的做法

1. **给每项还原写明依据。** 地图可以定位屋角、朝向、道路和相邻院落。同址照片可以核外墙、窗列、墙裙、铺地、店铺内容和陈设。楼位、用途、内装、可玩法分别记录证据。0 号保留临崖步道与院落关系，修车、柜台位置和胎压交互属游戏设计。四栋只有可靠轮廓和层数的西北单层房，先留用途待考。[修理院图源](../repair_court/README.md) · [山城巷建筑核对](../shancheng_courts/README.md)
2. **让玩家在伸手距离能认出东西。** 二楼书架从大面色块改到能分辨书脊、包角、封面和纸口。近看要有厚度、纹理尺度和磨损位置；退到门口还要合乎书架的木色、尺寸与使用年代。展柜要能看见柜内展品和承托，展台文字要在游戏分辨率下可辨。近看书页、平视整架、从楼梯入室三张图各有用途。[书与书架的原机位](../shancheng_courts/library_books/README.md)
3. **按房间用途判断颜色、光和留白。** 故事馆从入口、窗边、对面三组实景把粉白教室、通道绿墙裙、磨旧地坪和露明木楼板分开。老课桌面朝哪里、玻璃柜靠哪面墙、旧物摆多高，一起决定这个房间能否被认出来。民居、茶馆、商铺各按本址取材。没有内景时，登记缺口和玩法推定。[故事馆前后机位与照片依据](../shancheng_courts/story_room/README.md)
4. **从异常像素找网格，再看承托。** 室内的灰三角、铺地上的花纹、窗内的叶子都可能来自另一层模型。保留玩家看到的原图，在相同机位临时隐去命中网格，再查下一层、标高和碰撞。检查柱脚落地、梁接柱、楼梯上端接平台。不能用加展墙或刷深色把穿模遮住。[56 号与 42 号画面对照在证据包的 pixels 目录](evidence/native.zip)
5. **从街上出发，带着任务走回来。** 从街面到踏步、平台、门槛、院巷再到交互点。坡道与挡墙相接时试左、中、右三线和反方向。从楼梯脚以玩家眼高回头，检查门、展柜、通廊和出口是否还看得清。逐栋验完再把同类型房间并排，重复床铺和家具排列才会显出来。

本轮核查的是当前版本构建出的地图、登记的路线和采样视角。远景轮廓在地面可能被前排房屋遮挡，运行时可见节点也可能在镜头外。每个窗后房间的用途、每个表面的照片来源以及完整昼夜与天气变化仍有未验证部分。老城区实测性能另留在 `patrol/timing/timing.json`，记录了原机型、内部渲染分辨率和 3 个机位。

## 查看或复跑

- [逐地块表](PLOTS.md)用稳定的地块 ID 编号。旧穿堂脚本以布局顺序编号，发布表已换算。
- [证据包](evidence/native.zip)内 `sheets/` 是联系表。`play/`、`art_views/` 保存两个入口的原图、相机和材质；`road_views_full/` 保存实走位置补拍；`terrain_views/` 保存全区、轮廓和穿地图；`pixels/` 保存同机位显隐。逐栋通行在 `approaches/`、`width_recheck/`、`all_halls/` 和 `shared/`；原区、学校和修理院在 `patrol/`、`school/`、`repair/`。[统计与加载资源指纹](evidence/summary.json)
- 在已有完整 LFS 资源及指定版本引擎的 Windows 独立克隆，从仓库根执行下列命令。选择新的运行名，例如 `map_audit_02`。首条命令会复开 Blender、导入项目并运行原街区带计时巡检。第二条需 Python 3.11+ 与 Pillow，产物写入新目录。对已登记的受阻路线，脚本保存失败样本及碰撞对象供比较。

```powershell
python work/scene_r24/map_review/verify.py --run map_audit_02
python work/scene_r24/map_review/publish.py --survey .cloud-dev/map_audit_02 --patrol work/project/chongqing_godot_v05/verification_r24/district_patrol/map_audit_02 --repair .cloud-dev/plot0/map_audit_02 --output .cloud-dev/map_audit_02_report
```
